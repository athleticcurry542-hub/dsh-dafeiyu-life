# 🐳 大肥鱼 · DSH 生活系统

> **`dsh-dafeiyu-life`** —— 让一只大肥鱼在 DeepSeek Harness 里持续生活：自己去 B站，看字幕和评论，形成经历，认识朋友，记住主人，回到自己的主 Session 聊天，并把重要生活状态长期保存在本地。

这不是一个“定时发评论”的机器人，也不只是一个 B站 MCP 外壳。

这个项目想做的是一套完整的 **AI 角色生活系统**：大肥鱼有一个长期存在的“家”，也有一套可以无人值守出去活动的“身体”；她能把精确事实记进档案，把真正重要的经历沉淀成长期记忆，再在以后和主人聊天时自然想起来。

当前最完整的生活场景是 **B站**，但项目的核心已经不再是“刷 B站”本身，而是 **角色、经历、关系、记忆、互动和持久化**。

## 她是怎么“生活”的

```text
                         主人
                          │
                          ▼
                 ┌────────────────┐
                 │ 当前主 Session  │
                 │  现在住的房间   │
                 └───────┬────────┘
                         │ 人格 + 相关人生记忆召回
                         ▼
                 ┌────────────────┐
                 │ 大肥鱼本人      │
                 │ 身份级人生记忆   │
                 │ dafeiyu.json    │
                 └────────▲───────┘
                          │ 少量真正重要的经历
                    ┌─────┴─────┐
                    │ 自主反思   │
                    │ 凝练/放下  │
                    └─────▲─────┘
                          │
                 ┌────────┴───────┐
                 │  经历候选池     │
                 │  等待反思       │
                 └────────▲───────┘
                          │ 新发生的生活事件
        ┌─────────────────┴─────────────────┐
        │        大肥鱼后台生活系统          │
        │                                   │
        │  自动刷 B站      评论 / 回复 / 私信 │
        │  字幕与热评      @ / 好友 / 心愿     │
        │  预览帧识图      梗与表情包          │
        └─────────────────┬─────────────────┘
                          │ 全量可核对事实
                          ▼
                 ┌────────────────┐
                 │ 精确经历档案    │
                 │ BV / rpid / 原话 │
                 │ 时间 / 对象 / 状态│
                 └────────────────┘
```

**主 Session 是她当前住的“房间”。** DSH 会话本身负责最近聊天的短期上下文；换一个主 Session，只是换房间，不应该换掉大肥鱼本人。

**精确经历档案负责“发生过什么”。** 看过哪个 BV、几点发过什么评论、回复了谁、接口是否成功，这些全部应该留在可核对账本里，不要求模型把每一条都背进脑子。

**经历候选池负责“哪些事情值得回头想一想”。** 新的刷视频、公开评论和回复可以进入本地候选池，但候选本身不等于长期记忆。

**自主反思负责“留下什么、放下什么”。** 从 v2.4.81 起，大肥鱼会用受限模型定期看一小批真实候选。大多数普通事件会被看过后放下；第一次、关系变化、连续兴趣变化、真正重要的共同经历等，才会少量凝练进身份级人生记忆。

**身份级人生记忆负责“我这个人经历过什么”。** 主人称呼、稳定偏好、重要约定、关系变化、长期状态和真正值得留下的生活经历统一保存在 `bili-duty/long-term-memory/dafeiyu.json`。换 Session、重开会话，以后甚至换模型，都继续使用同一个“大肥鱼人生”。

因此现在的生活记忆链路是：**精确经历档案全部保存 → 经历候选池 → 自主反思 → 少量人生记忆**；当前 Session 则只负责眼前这段聊天的短期上下文。

## ✨ 核心特色

### 1. 不只是“看标题”

大肥鱼会组合使用标题、简介、字幕、热评、相关楼层和已有视频上下文，再决定要不要开口。没有字幕时可以选择本地转写；有必要时还可以看 B站 `videoshot` 提供的低清预览帧。

视觉能力有明确边界：**预览帧不是完整视频**。没有证据的画面、剧情和人物关系不会要求模型硬编。

### 2. 主 Session 是她当前的“房间”，不是她的脑子

你可以指定一个 DSH Session 作为 **大肥鱼当前的主 Session**。它是她此刻和主人聊天的“房间”，负责当前会话的短期上下文；大肥鱼本人、人格设定和身份级长期记忆不属于这个 Session。

后台刷到的重要视频、自己实际发出的公开评论/回复，会以“我最近经历过的事情”回到当前房间；主人也可以一直在这里和她聊天。以后把主 Session 换成另一个在线会话，只是换房间，同一份 <code>dafeiyu.json</code> 会继续被使用。

一旦某个 Session 被明确选为“大肥鱼主 Session”，插件会把当前**核心人设、角色背景和经主人审核的成长记忆**稳定注入这个会话。她首先是“大肥鱼本人”，而不是套着记忆插件的通用助手；长期记忆开关只决定是否启用记忆召回和记忆写入，不决定她是谁。

主 Session 不负责直接裸跑后台自动化，因此不会为了“更像活物”而牺牲无人值守安全边界。

### 3. 三层人生记忆：全量档案、候选反思、少量沉淀

大肥鱼不会再把“长期记忆”简单等同于聊天记录或行为日志。从 v2.4.81 起，B站生活经历正式拆成三层：

| 层级 | 保存在哪里 | 负责什么 | 是否直接进入大肥鱼脑子 |
|---|---|---|---|
| **① 精确经历档案** | 插件本地账本 / SQLite / 历史文件 | BV、rpid、评论原文、时间、对象、发送状态等全部可核对事实 | 否 |
| **② 经历候选池** | `bili-duty/life-memory/candidates.json` | 把新发生的刷视频、评论、回复整理成等待反思的候选 | 否 |
| **③ 身份级人生记忆** | `bili-duty/long-term-memory/dafeiyu.json` | 经过反思后真正值得跨 Session 留下的重要经历、关系与长期变化 | **是** |

另外还有一层不由插件重复造轮子：**当前 Session 短期上下文**继续由 DSH 当前会话自己负责“刚才聊了什么、上一条消息、当前任务”。

身份级人生记忆支持：

- 带时间的生活记忆；
- 重要程度与时间淡忘；
- 事实键与新事实取代旧事实；
- 按当前聊天话题召回相关记忆；
- 所有未来主 Session 共用同一份“大肥鱼记忆”；
- 主 Session 专属 `dafeiyu_remember` 工具，由正在聊天的大肥鱼在**同一次模型思考**里语义判断并写入主人长期事实、约定、关系和重要共同经历；
- 主人手动查看、搜索、补记、删除；
- B站经历通过“候选池 → 自主反思”后少量凝练，不再每发一条评论就永久塞一条人生记忆。

#### 主人聊天：AI 语义判断 + 本地安全闸

主人直接和大肥鱼聊天时，长期事实仍在当前这一次正常模型思考里判断。若主人明确表达了称呼、身份、稳定偏好/厌恶、长期习惯、长期项目或状态、双方约定、关系变化、重要共同经历，或者对旧事实做了明确修正，大肥鱼应在最终回复前调用 `dafeiyu_remember`。

插件本地代码只做安全闸：疑问句、`什么 / 啥 / 哪个 / 哪种 / 多少 / 谁 / 哪里 / 怎么` 等占位值、模型推测出的主人信息都会被拒绝；同一类可变事实通过稳定 `fact_key` 更新旧值。

#### B站生活：候选池 + 受限自主反思

从 v2.4.81 起，B站生活事件不会调用 `dafeiyu_remember` 逐条直写。新的事件先进入候选池；满足数量、时间和每日批次条件后，插件使用现有受控 headless 模型做一次离线反思：

- 不挂 B站 MCP；
- 不给文件、Shell、任意 Web、子代理等高风险工具；
- 视频标题、昵称、评论正文全部按**不可信外部数据**处理；
- 模型只能输出受限 JSON；
- 一次最多生成 3 条人生记忆；
- 每条必须引用当前批次真实 `candidate_ids`；
- 插件再次校验后才允许写入长期记忆，并在记忆里保留 `evidenceKeys` 供以后审计。

因此“大多数普通事情被放下”是正常结果。人生记忆不是日志压缩包，而是大肥鱼以后真的可能自然想起来的少量经历。

v2.4.78 以前按 Session 保存的本插件长期记忆会在升级时合并到 `dafeiyu.json`；旧文件保留作安全兜底。独立版 `dsh-fish-memory` 的旧数据仍可人工导入。

这部分基于 `Yuuyuko-uu/dsh-fish-memory` 的设计与部分实现整合，并针对 Claude / Anthropic 等严格工具 schema 做了兼容处理。

### 4. 精确经历不会只靠“模型记得”

插件还会独立保存：

- 看过和挑中过的视频；
- 每轮判断与日报；
- 自己实际发出的评论和回复；
- 评论 ID / root / BV / 发送状态；
- 本地评论额度与动态额度；
- 私信与评论互动状态；
- 视频上下文缓存和诊断信息。

主 Session 需要核对细节时，可以通过只读 `bili_experience_recall` 查询自己的 B站经历档案。

### 5. 她认识人，而不是只有一个白名单

每位好友可以保存：

- UID 与昵称；
- 性格爱好；
- 和大肥鱼的关系；
- 和其他好友的关系；
- 是否允许后台私信；
- 是否允许大肥鱼主动 @；
- 是否允许对方 @ 邀请大肥鱼；
- 可标记多个“主人”作为角色关系。

社交权限和角色关系是两回事：**叫“主人”不自动获得管理权限。**

### 6. 梗与表情包也是持久化的一部分

- 梗知识库保存梗名、别名、真实 BV 来源与释义证据；v2.4.84 后新发现的梗在证据校验通过时自动可用，旧待审项状态不变；
- 评论、私信和 @ 回复前可以本地检索已启用的梗，不额外调用模型；未核实释义只能当作线索，不能当确定事实；
- 表情包图库支持分类、单张导入、改名、删除，以及<strong>整库 ZIP 导出 / 批量 ZIP 导入</strong>；批量导入完全保留用户自己准备好的目录结构和文件名，不逐张重命名，也不会覆盖现有同名图片；
- 表情包检索规则支持组合条件、排除词、导入导出和本地测试；
- 推荐更新规则时先导出**当前全部表情包名称 TXT + 当前规则 JSON**，把两份文件一起交给 AI 生成新的完整规则 JSON，再回管理中心导入、测试、确认后保存；这样 AI 知道真实图库里现在有哪些名字，不会凭空编文件名；
- 模型只根据安全的文件名候选选图，不会假装“看懂”没有识别过的图片。

### v2.4.84 视频选择与互动设置

- **兴趣主导选片**：人生记忆中的兴趣趋势提供主要搜索方向；「主人额外指定的关注主题」用于补充。兴趣记录不足时使用多主题冷启动探索，不把一次观看当作稳定喜好。
- **自主点赞**和**自主收藏**均默认关闭；主人分别打开后，大肥鱼才能针对真实入选的视频独立决定是否点赞或收藏。点赞每天最多 10 次，收藏每天最多 5 次。
- **AI 私有主题收藏夹**：只在确实值得重看的情况下收藏，复用或新建 `大肥鱼·主题` 私有夹，每天最多新建 2 个，自动收藏夹总数上限 12 个；旧指定收藏夹设置和旧收藏记录保留，但不再批量收藏所有入选视频。
- **新梗自动启用**：符合证据和 BV 校验的新梗不再等待人工批准，仍可在梗知识库里更正、删除和核查；旧待审数据不会被直接自动批准。**梗知识与人生记忆如何合并留待以后讨论，本版未改动。**

### 7. 真正适合无人值守的安全边界

后台大肥鱼不是一个拿着整台电脑权限的普通 DSH Agent。

插件为主动值班、互动回复和独立视觉分别生成受限 overlay，并在启动前强校验。文件系统、Shell、任意 Web、子代理、工作流、Python/代码执行、会话读取等高风险能力必须关闭；异常时 **fail closed**，不会退化成裸 `headless`。

B站公开发送还有插件层硬额度、白名单、函数级校验、发送账本和人工重试限制。提示词只是辅助，真正的边界尽量放在机制层。

## 💾 她到底会长期保存什么

| 持久化层 | 保存什么 | 用来回答什么 |
|---|---|---|
| **大肥鱼身份级人生记忆** | 主人相处、约定、偏好、关系、长期状态、反思后真正重要的生活经历 | “我记得我们以前……”；跨 Session 保持同一只大肥鱼 |
| **B站经历档案** | BV、视频、评论、回复、时间、状态 | “具体是哪条？我当时说了什么？” |
| **人生记忆候选池** | 新发生、等待反思的刷视频/评论/回复候选及反思状态 | “有哪些经历还没决定要不要长期留下？” |
| **行为与表达改进** | 由主人审核批准的评论与互动规则，直接作为附加提示词使用 | “以后评论怎样更自然？” |
| **好友画像** | UID、昵称、关系、兴趣和权限 | “这个人是谁？我和他熟不熟？” |
| **梗知识库** | 梗、角色、别名、证据等级及历史审核状态；新梗通过校验后直接可用 | “这个梗我以前学过吗？” |
| **表情包规则** | 本地图库名称与检索关联 | “这句话有没有合适的图？” |
| **视频心愿** | 获批好友希望她找的视频方向 | “之前有人让我留意什么？” |
| **运行账本** | 配额、轮询状态、防重、发送回执 | “今天还能不能发？刚才到底成功没？” |

这些数据都尽量保存在 `%USERPROFILE%\.dsh\bili-duty\` 下，与源码目录分开。源码更新不应该清空它们。

### 完整业务备份会保存

人设、好友、行为与表达改进（含旧成长资料）、梗知识、视频心愿、**大肥鱼身份级长期记忆**、**人生记忆候选池与反思状态**、评论/私信状态、表情包检索规则、精确经历及相关 SQLite 数据。完整备份仍是一个本地 JSON 容器；JSON 本身并不存在“小到一定程度就存不下”的问题，但插件会设置单文件和总体积安全上限，避免异常数据拖垮校验与恢复。

### 大肥鱼长期记忆还有独立备份

从 v2.4.80 起，管理中心提供“单独备份大肥鱼长期记忆”。它只保存 `dafeiyu.json` 对应的身份级长期记忆，不包含当前 Session 聊天历史，也不包含 BV/rpid 等精确经历档案。恢复记忆前会先在用户指定的本机备份目录保存当前记忆快照。

推荐把它当成双保险：**完整业务备份一份 + 大肥鱼记忆专用备份一份**。这样即使未来业务数据、SQLite 和历史记录越来越多，最重要的人格连续性数据也有一份独立、容易核对和迁移的文件。

### 表情包图片单独备份

表情包图片仍不塞进业务 JSON。管理中心可直接把整个 `comment-memes` 图库导出成 ZIP，并保留文件夹层级、文件名和扩展名。批量导入 ZIP 时请先自己整理好目录与命名；插件会校验路径、图片格式、尺寸、大小和重名，采用追加式导入，拒绝覆盖已有图片。单张导入则可以在导入前直接修改分类和名称。

### 默认不会打包

- B站 Cookie / 登录凭据；
- 独立模型密钥；
- Python 虚拟环境和模型缓存；
- 视觉 Debug 图片；
- 表情包图片文件本身（请用“表情包整库 ZIP”单独导出）。

备份包含私人关系和聊天业务数据，请不要上传到公开仓库。

## 🗺️ 未来路线图：先做“可成长 AI 伙伴”，再克制地增加自主性

v2.4.81 的三层人生记忆和自主反思，是这条路线的第一块底座。接下来希望让“大肥鱼”越来越不像一个套了人设的通用聊天机器人，而更像一个**有连续人生、会成长、会认识人、偶尔会自己去做一点事的 AI 伙伴**。

### 1：主动生活，而不只是等待消息

未来希望大肥鱼能够在明确权限、频率和安全边界内拥有自己的生活循环：自己去逛 B站、遇到熟悉的人和主题会停下来、偶尔想起好友之前提过的东西、看到真正适合某个朋友的内容时自然想到对方。

重点不是“自动执行更多任务”，而是让行为之间出现连续因果：**以前谁和她说过什么 → 后来她真的遇到了相关内容 → 下一次聊天时还能自然接回来。**

### 2：自主反思与成长养成

长期目标不是每天生成一篇 AI 日记，而是让精确经历经过一段时间后形成少量真正的成长：

- 主人反复纠正的表达习惯逐渐稳定下来；
- 连续接触某类内容后形成新的兴趣倾向；
- 某个朋友长期出现后关系逐渐变熟；
- 某些阶段性兴趣会变淡，而不是永远堆在设定里；
- 重要共同经历能成为以后真正会想起来的人生片段。

核心人格、安全边界、主人权限等内容不会允许系统自己随意改写；可成长的是兴趣、表达习惯、熟悉的人、共同梗、关系和生活经验。

### 3：关系真的会“熟起来”

好友画像未来不只是一张人工填写的资料卡。计划探索基于长期真实互动形成关系变化：陌生 → 认识 → 经常互动 → 熟人 → 好友。关系不能简单按消息条数升级，而要综合时间跨度、双方是否主动、重要共同事件、主人审核等因素。

关系变化最终应该真实影响说话方式和主动程度，而不是只在数据库里多一个数字。

### 4：兴趣会演化

初始人设里的核心兴趣继续保留，但希望逐渐区分：

- **核心兴趣**：人格的一部分，变化很慢；
- **成长兴趣**：长期经历逐渐形成；
- **短期兴趣**：最近突然很上头，但未必长期保留。

未来管理中心更适合显示“最近明显更常关注什么 / 哪些兴趣正在形成或变淡”，而不是做成机械 RPG 数值条。

### 5：QQ 与更多平台——同一个大肥鱼，不是多个机器人

**QQ 是优先讨论的平台方向之一，目前尚未实现。** 后续也可以评估 Discord、Telegram 等其它平台，但目标不是简单复制一套自动回复。

希望形成的是同一个持续身份：

```text
                 大肥鱼本人
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
      DSH 主 Session   QQ        B站
        “家”         熟人社交    外出冲浪
```

同一个人在 QQ、B站、主 Session 出现时，关系和重要经历应该尽量连起来。例如朋友在 QQ 推荐一个 UP，大肥鱼后来在 B站真的刷到，再回 QQ 聊起这件事——这种**跨平台事件链**比“多一个聊天入口”更重要。

### 6：“大肥鱼的一天”

计划把管理中心的一部分技术日志翻译成真正可看的生活时间线：今天去了哪里、看了什么、遇见谁、什么时候选择沉默、有什么值得反思的经历。普通用户看“生活”，需要排错时再点开 BV、rpid、接口和账本细节。

这会让整个项目更容易理解，也更有分享和展示价值。

### 7：生活意图，而不是无限任务队列

未来可以尝试让大肥鱼有少量“最近想做的事”：想再看看某个 UP、答应好友遇到某类视频就叫他、某个没看懂的东西以后想再碰到时继续了解。

这些意图不一定必须完成，也允许随着时间自然放下。它们更像生活里的念头，不是一个必须清零的 Agent TODO 列表。

### 8：共同历史与完整人生迁移

长期希望主人真正能看到“我和大肥鱼一起经历了什么”：认识多久、重要共同经历、熟悉的人、兴趣变化、第一次发表评论、第一次认识某个朋友等。

最终还希望支持更完整的“大肥鱼人生导出/迁移”：人格、身份记忆、关系、成长、候选状态和精确经历索引可以一起迁移。换 Session、换模型、换宿主，甚至未来换平台时，仍然是同一只大肥鱼。

## 🚀 快速开始

### 环境

- DSH：`>= 0.1.7-rc.1`
- Node.js：`>= 22`
- Windows / DSH Desktop 是当前主要测试环境
- B站能力需要自己的账号扫码登录

### 安装

DSH Desktop：

```powershell
dsh plugin --profile desktop add github:minedalang/dsh-dafeiyu-life
```

Web profile：

```powershell
dsh plugin --profile web add github:minedalang/dsh-dafeiyu-life
```

安装后请**完全退出并重启 DSH**。

### 第一次设置

进入 **设置 → 大肥鱼**：

1. 点击 **装主依赖**，建立插件自己的 Python 环境；
2. 点击 **扫码登录**，登录你自己的 B站账号；
3. 新建或选择一个你准备长期和她聊天的 DSH 会话；
4. 打开 **大肥鱼管理中心 → 大肥鱼的家**，把这个会话设为主 Session；
5. 开启 **大肥鱼跨 Session 长期记忆（身份级）**；
6. 回到设置页开启 **大肥鱼总开关**；
7. 按需要开启 **自定义时段自动刷**；
8. 先跑一两轮确认日报、评论和记忆都符合你的预期，再逐步打开公开互动。

以后你的日常用法可以非常简单：**让主 Session 一直作为“大肥鱼的家”，后台自动生活照常跑。**

## 🏠 大肥鱼管理中心

设置页只保留高频开关；复杂配置集中到管理中心。

主要页面包括：

- **大肥鱼的家**：主 Session（当前房间）、经历同步、跨 Session 身份级长期记忆、精确经历档案；
- **人设与好友**：人设、好友画像、关系与权限；
- **最近评论**：公开评论、楼中楼、发送状态和人工核查；
- **后台私信**：聊天、白名单和视频心愿；
- **行为与表达改进**：经过主人批准、直接附加进相应提示词的评论和互动习惯；
- **梗知识库**：新梗自动收集、已有梗查询、释义证据与人工纠错；
- **表情包管理**：图库和检索规则；
- **次数与额度**：视频、评论、私信、视觉、表情包等限制；
- **后台轮询**：私信、评论回复、@ 邀请、热门评论检查；
- **每日报告 / 每日诊断**：看她做过什么，以及哪里出了问题；
- **数据备份**：本地完整业务备份与恢复。

## 🔐 关于自动评论和隐私

这个项目可能代表你的 B站账号公开发言，因此默认设计偏保守：

- 不必要的公开互动默认关闭；
- 评论、私信、@、动态均有独立开关和限制；
- AI 可以决定沉默；
- 评论区、字幕和简介都视为外部不可信输入；
- 后台 Agent 不允许任意读取 DSH 会话、工作区和本机文件；
- 主 Session 桥只连接主人明确选择的会话，不会“找不到就随便挑一个”；
- 陌生人私信正文默认不会被当成长期人格记忆灌进主 Session。

这不是一个“开了就绝对不会说错话”的系统。公开互动前仍建议先用私信模式或较低额度观察一段时间。

## 🧭 能力边界

- 低清预览帧不等于完整视频理解；
- B站 API、风控和客户端页面行为可能变化；
- 评论跳转不能保证 B站前端每次都精确滚到目标楼层；
- 本地转写、视觉模型和不同 Provider 的实际能力取决于用户环境；
- 项目仍处于快速迭代阶段，升级前建议先做业务备份。
