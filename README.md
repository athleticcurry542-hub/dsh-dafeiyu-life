## 大肥鱼 Plus 的特色

| **重点：高能片段预览帧** | 使用 B站播放器 `videoshot` 低清预览图和可用的时间索引，**优先抽取高能时间点帧**，不足时回退均匀采样。配合支持视觉输入的模型识别画面、角色、动作和视觉梗；可配置每视频取图数量与诊断。**这不等于观看完整视频**，没有识别到的画面不会编造。 |

### 把一个 DSH 会话变成“大肥鱼的家”（v2.4.75）

1. 在 DSH 里新建或选一个你准备长期与大肥鱼聊天的普通会话，并保持它打开。
2. 打开「大肥鱼管理中心 → 大肥鱼的家」，刷新在线会话，选择它并保存；默认首次只建立当前档案基线，不会把全部旧历史突然灌进去。
3. 推荐另外安装 `github:Yuuyuko-uu/dsh-fish-memory`，重启 DSH 后在「设置 → 鱼的记忆」**只给这个主 Session 开启记忆**。这是第三方可选插件，不由本插件自动安装或读取其数据。
4. 以后照旧开启大肥鱼总开关和自定义时段。后台刷 B站仍由受限 headless Agent 完成；有新的重要经历时，插件最多按设置的频率把经历批量投到主 Session。
5. 想把升级前的近期生活补进去，可在「大肥鱼的家」点「导入最近 7 天重要经历到队列」，确认后再点「现在同步」。

主 Session 不是 B站数据库：所有跳过视频、精确 BV/rpid、发送状态、额度和权限仍以本插件档案为准。桥只同步已挑中的视频和大肥鱼自己实际发过的评论／回复；不会复制别人的私信全文，也不会读取其它 DSH Session。 当主人追问过去的具体经历时，主 Session 还可使用只读 `bili_experience_recall` 查询插件档案中的 BV 和自己已经发出的公开评论/回复；该工具不读取其它 DSH Session、陌生人私信，也不联网。

### 视觉能力的重要边界

「次数与额度」中 **每视频取帧数（1–3）** 与 **独立视觉模型每日调用次数（0–200，默认30）** 是两套独立设置。默认的「复用视频 Agent」模式不使用每日独立调用账本；因此即使识别过预览帧，该账本也可能显示 `0 / 30`。独立调用按启动尝试计数，失败仍可能消耗次数，缓存命中不再扣次。

Plus 的取帧依赖 B站 `videoshot` 预览素材：接口可能缺失、图片会很模糊或连接失败。插件尽可能选择有代表性的**预览帧**，不意味着可逐秒播放／理解完整视频。公开评论与 @、点赞／动态投递仍受 B站接口、权限与风控影响，模型也可能判断沉默。

## 快速开始

### 运行环境

- **DSH**：`>= 0.1.7-rc.1`。
- **Node.js**：项目声明要求 `>= 22`（由 DSH 宿主提供运行环境）。
- **Python 运行环境**：依赖 Python MCP；可使用 Python 3.10+ 或 `uv`。插件提供主依赖安装流程，必要时会尝试下载 `uv` 并在自己的数据目录创建虚拟环境。
- **网络与账号**：需要访问 B 站相关接口，并使用自己的 B 站账号扫码登录。特定接口可能受到网络环境或 B 站风控影响。

### 1. 安装插件

**DSH Desktop（桌面版）：**

```powershell
dsh plugin --profile desktop add github:minedalang/dsh-bili-scroll-plus
```

**Web profile：**

```powershell
dsh plugin --profile web add github:minedalang/dsh-bili-scroll-plus
```

安装后**完全退出并重新启动 DSH**，使插件加载生效。请使用本 Plus 仓库安装；不要把上游项目 `dsh-bili-scroll` 当成 Plus 的升级源。

### 2. 初始化并登录

在 DSH **设置 → 刷B站** 中：

1. 点击 **装主依赖**，完成插件私有 Python 环境初始化。
2. 点击 **扫码登录**，使用自己的 B 站客户端确认登录。
3. 按需配置选片来源与关键词；到管理中心的「次数与额度」设置每天／每轮选片数，到「人设与好友」查看默认提示词或进行自定义，再使用 **现在跑一轮** 验证。
4. 确认日报及判重正常之后，再决定是否启用**自动评论、后台私信或评论互动**。

如需处理无字幕视频，可另外开启本地转写并安装对应依赖；只开转写开关不等于已经安装了转写模型。

### 3. 更新插件

```powershell
dsh plugin --profile desktop update dsh-bili-scroll-plus
```

如果你使用的是 `web` profile，将命令中的 `desktop` 改为 `web`。更新后同样建议重启 DSH。**插件更新不会要求清空运行数据目录。**

## 管理中心

**本地数据备份与恢复（v2.4.68）：** 在「数据备份」页点击「下载完整数据备份」；保存生成的 JSON 文件。升级、重装或迁移后可选择该文件并确认恢复。保存所有生效设置、人设、好友 UID 关系与权限、成长经验、梗知识 SQLite、视频心愿、各类历史与防重复发送状态。恢复前自动在插件家 `bili-duty/backups/` 备份现有数据；恢复后重启 DSH。**不包含表情包图片、B站登录凭证/Cookie、视觉密钥及模型缓存**；账号可能需要重新扫码。备份包含私人资料，禁止上传到公开仓库。默认单次业务文本总量 32 MB，超过限制会明确提示，不静默丢数据。


在 DSH **设置 → 刷B站 → 打开管理中心** 进入。管理页面由插件已有的本机 HTTP 服务提供，**不需要单独启动 Node 服务，也不使用固定的 18763 端口**。

| **最近评论** | 看主评论／回复分类、BV 评论定位、对方身份与上一条评论预览，核对近 24 小时回复额度。 |

## 主要配置与使用建议

- **选片与自定义自动运行**：可配置多个本机时间段（支持跨午夜）及 1～720 分钟的运行间隔；升级后旧中午／夜间模式不再生效，需要自行保存新时段。建议先手动跑一轮并核对日报。候选视频不等于已挑选视频。
- **公开评论和 @**：在「人设与好友」用一份 UID 名册勾选三种权限；AI 可按内容选择邀请对象，但不会凭人设自行增加可 @ 的账号。评论、动态、收藏和私信受各自开关与限额控制。
- **表情包**：在管理中心「表情包管理」上传、预览、重命名、删除 PNG/JPG/GIF/WebP 图片；也可继续手动放在本地 `comment-memes/` 中建立分类。功能默认关闭，成功调用发布接口也不代表 B站 页面立即可见。
- **人设与成长**：人设由用户填写；通过审核的评论表达经验稳定影响评论风格；长期兴趣仅影响自然偏好及选片判断；视频经历、角色关系按主题检索，不自动修改搜索词或核心人设。
- **视觉识别**：只在需要画面信息且所选 DSH 模型支持的情况下使用。低清预览图不能代表完整视频，更不能用于猜测未看到的细节。
- **临时视频心愿**：已获批的私信用户明确请求找美食、宠物等支持的主题时，保存一个最长 30 天的临时心愿（默认可尝试 @ 3 次，可在管理中心设置 1～10 次）；只在 AI 选中且实际视频元数据匹配时尝试 @，达到次数后停止。关闭自动评论或 @ 模式后不会发送；B站接受评论不代表通知送达。可手动取消心愿。
- **每日私信上限**：支持 0～1000，0 代表不设每日私信总额限制，**该字段只管自动私信，不管公开评论**；仍受单次轮询和小时限速等保护；与旧版本一致，信任白名单不受全局每日私信配额约束。
- **后台评论回复**：须手动开启「后台回复别人对我的评论」和插件总开关。回复大肥鱼自己的主评论、及她在别人评论下发表的回复，会优先回应；按两个场景分别设置每 UID 的近24小时回复上限。只有本地评论账本或成功发送回执能确证归属的评论启用优先机制；未能确认归属或首次启动时无法判断新旧的通知可能被跳过。后台公开评论近24小时上限是 1～1000，并受独立的「公开评论每日硬上限」（含原创评论）制约，硬上限为 0 时无法发公开评论。
- **后台私信上下文**：可以配置最近 0～80 条消息参与生成，0 表示不向模型传递旧历史；上下文按 UID 隔离，原本的旧摘要保留。与公开评论的额度独立。
- **后台私信**：建议先配置白名单和频率限制。B 站限流、DNS、代理和网络阻断等问题无法仅靠插件的请求重试解决。

## 本地数据

运行数据与插件源码分离。在通常的 Windows Desktop 环境中，数据目录为：

```text
%USERPROFILE%\.dsh\bili-duty\
```

常见文件及子目录：

| 路径（相对数据目录） | 用途 |
|---|---|
| `config.json` | 本地插件设置。 |
| `bili_credential.json` | B 站扫码登录凭据，**请勿上传 GitHub 或发到群里**。 |
| `duty.log` / `duty.log.1` | 插件运行日志与轮转备份。 |
| `out/`、`reports/`、`digest/` | 每日报告、单条视频笔记与归档。 |
| `seen.md` | 已看／已挑选视频的判重记录。 |
| `meme-memory.sqlite3` | 梗知识和来源证据；不保存图片文件。 |
| `comment-memes/` | 本地可选评论表情包素材（沿用旧目录名称，无需迁移）。 |
| `persona-growth/v1.json` | 成长候选、审核结果及经验记录。 |
| `dm-autoreply-state.json` | 私信自动回复、申请与临时视频心愿的本地持久化状态。 |
| `video-wish-claims/` | 临时 @ 发送占位、B站评论回执及防重复状态，不保存私信正文。 |
| `mention-diagnostics/` | 公开评论 @ 诊断。 |

> **隐私提示：** 本地存储不等于完全离线运行。搜索、发评论和私信需要访问 B 站；使用模型分析则取决于你在 DSH 中配置的模型服务。公开反馈问题前，请从日志和截图中移除 Cookie、UID、私信正文、API Key 等信息。

## 常见问题

<details>
<summary>安装后找不到「刷B站」设置</summary>

确认安装到正在使用的 DSH profile、DSH 已完全重启，并检查插件是否激活。可先确认 DSH 版本符合 `package.json` 中的要求，再查看 `duty.log` 中的宿主依赖或加载错误。

</details>

<details>
<summary>管理中心打不开，但插件可以正常刷视频</summary>

先在设置页点击「打开管理中心」。若打不开，检查 `duty.log` 是否有路由或打开网页错误。管理页面位于 DSH 本机服务的 `/api/bili-duty/manage`，端口随实际宿主而定；不需要单独启动旧版 `persona-growth-manager.mjs`。

</details>

<details>
<summary>出现 `DM poll failed: fetch failed`</summary>

在管理中心的「后台私信」点击**测试私信接口连接**。插件仅对只读请求进行有限重试，不重试发送操作；如遇 DNS、TLS、网络代理或 B 站限流问题，需结合日志中的目标主机、底层错误码排查。

</details>

<details>
<summary>视频没有字幕，或视觉识别不成功</summary>

未启用或未安装本地转写时，无字幕视频可能被跳过。预览识图需要 B 站提供可抓取的预览帧，并且所选模型能正确接收图片；「测试抓图成功」不代表 AI 已正确理解画面。

</details>

<details>
<summary>更新插件会丢掉原有梗知识或成长记录吗？</summary>

设计上代码与用户数据目录分离；常规覆盖源码／插件更新不应清空 `bili-duty`。重要数据请自行备份，尤其是 `meme-memory.sqlite3`、`persona-growth/`、`config.json` 和登录状态。

</details>
