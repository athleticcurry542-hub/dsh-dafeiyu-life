- **大肥鱼视情况自主决定（默认）**：普通评论可以一句 @ 都没有；大肥鱼真的想分享时，在 `bili_reply` 指定 `should_mention: true`，发送层才会插入整份名单，不再按固定概率随机 @。
- **永远不 @**：用户显式关闭时，即使模型想 @ 也会被发送层挡住。
- **每条都 @ 全部好友**：为需要强制邀请的场景提供可选策略；不建议频繁使用。
- **位置自然**：由 AI 建议句首、句中、句尾；句中无法自然断句时落在句尾。
- **多人名单**：每行 `昵称|UID`，可仅填写昵称但这种情况只能保证正文 @ 文本。已有 `mentionName` 自动作为空名单时的回退值。
- **私信收件人独立**：使用 `dmUid`，与公开评论名单互不影响（没填时仍可按老的 `mentionName` 查 UID）。
- **真实 @ 尽力发送**：全部名单都填写 UID 时，MCP 会尝试向 B站提交 `at_name_to_mid` 映射。接口成功只表示评论被接受；是否触发通知不能通过评论回执确认。UID 不完整时仅发送文字 @。
- **默认不改变用户公开评论授权**：仍需将投递方式设为「只评论」或「私信 + 评论」，并开启「自动发表评论」。独立后台评论互动仍沿用原先的频控，不会把所有好友拖进楼中楼。

## Plus v2.2.0：统一后台互动（默认不主动公开回复）

在 **设置 → 刷B站 → 互动** 可分别配置：

- **陌生人自动回复**：按 UID 设置最多 1–20 次；首条可选固定欢迎语（不花 Token），后续由 AI 生成。白名单照旧支持持续聊天。
- **后台回复评论通知**：每 3 分钟检查，首次启用只记录已有通知。
- **主动参与热门评论**：每 5 分钟检查最近 7 天挑选的视频，每视频查看前 N 条（默认5），优先“大肥鱼来吃饭”等明确互动内容；由 AI 决定是否回复，默认关闭。
- **公开评论限额**：每轮最多1条、近24小时最多5条（可设置）；复用持久化去重。

私信与评论共用一套后台调度和按需批量 AI 生成队列。没有需要 AI 回复的内容时不会调用模型；单条独立互动不保证省 Token。**旧版「跑一轮回复楼中楼」已经移除；回复评论统一由后台互动执行**。详见仓库根目录 `覆盖说明-v2.2.0.md`（如使用完整源码包）。

## 它做什么

- 按你填的关键词（留空则用内置那几组）搜近几天的视频
- **逐条读字幕原文再判断**（不看摘要）；没字幕的直接跳过 —— 除非你开了「本地转写」
- 写一份 Markdown 报告到 `out/<日期>.md`：每条含「为什么值得」+「它自己的一句话」；每条的段首固定写成 `### BV号` —— 插件数今天挑了几条，数的就是这些标题行
- 开着「自动评论」时，每轮发一条评论、**@ 你**一次（默认每轮 1 条，设置页可调到每轮最多 20 条）
- 可以在**峰谷时段自动跑**（DeepSeek 的优惠时段），省 token

## 装之前（一条前提，30 秒）

机器上要有 **`Python 3.10+` 或 `uv`** —— **有一个就够**：

- **有 `uv` 最好**：单个 ~32 MB 的 exe，**解压就能用、不用管理员、不用进 PATH**，而且它还能自己把 Python 拉下来；
- 只有 Python 也行（装官方安装器时记得勾 **`Add to PATH`**）；
- ⭐ **两个都没有？也没关系**：点「装依赖」时**插件会自己下一份 `uv` 放到自己的家目录**
  （单文件、约 15MB、**免管理员、不用进 PATH** ✓），之后全程自动 ✓
  · 它会**先直连 GitHub，不通就走国内加速代理**，还配了 PyPI 镜像兜底 ✓
  · 下载完会**核对官方 `sha256`**（对不上就丢弃换下一个源 ✓）—— 因为它下来的东西是要**被执行**的
  · ⚠️ **如果杀软 / Windows Defender 报这个下载**：把插件家目录 `%USERPROFILE%\.dsh\bili-duty\bin\` **加白**即可；
    不想加白也行，自己装一份 uv 或 Python 3.10+ 就绕过去了 ✓

> ✅ **已经做到了**（v0.1.1 起）：插件会**自己把 `uv` 下到自己的家目录** ⇒ 这条前提不用用户操心、也不用管理员权限。
> ⚠️ 万一它自己也下不动（有用户反馈桌面版上这条链路经常不通）：**手动放一份 `uv.exe` 到 `<家目录>\bin\`** 就行 ——
> 插件会**用那一份、跳过下载**（你的 `PATH` 里本来就有 `uv` 的话，它直接用那个）。

## 装不上 / 卡住时，先看这五条（都是用户实测撞过的）

1. **桌面版（DSH NEXT / 0.2.x）上"自动跑"会卡住** —— 有用户反馈：它起那一轮用的是
   `dsh --profile headless …`，桌面版上容易卡在那儿。⇒ **先用设置页的「现在跑一轮」手动跑**（那条是稳的）；
   能不能自动跑，等你确认过自己那台桌面版的版本与 profile 再说。
2. **「装依赖」卡住、或者扫码时一直不出二维码** —— 大概率是 0.1.0 那版（见开头那个按钮指纹，跑一次 `add` 就升级了）。
   不想升级也行，救急一句：`<家>\.venv\Scripts\python.exe -m ensurepip --upgrade`，再点一次「重装主依赖」。
3. **它下不动 `uv`**（桌面版上这条链路经常不通）⇒ 自己放一份 `uv.exe` 到 `<家目录>\bin\`，
   插件会用那一份、跳过下载。
4. **「本地转写」是两段式的** —— 只打开开关**不够**，还得点它下面那个「**装转写依赖**」。
   没装的时候，没字幕的视频会被**跳过**（报告里现在会写「**因无字幕跳过 N 条**」，你能一眼看出漏了几条）。
5. ⭐ **桌面版：装完设置页里根本不出现「刷B站」，日志只有一句 `1 entry did not activate … failed to import`** ——
   这是 0.1.3 及以前在桌面版上的一个真 bug：插件宿主半 import 的两个包是 *optional peer*，
   而桌面版 profile（`autoInstallPeers: false`）**不会装它们** ⇒ 插件整条不激活。
   **0.1.4 起已修**（不再裸 import 那两个包）。⇒ 升级一次就好：`dsh plugin --profile desktop add github:minedalang/dsh-bili-scroll-plus`。
   ⚠️ 我们自己也只在 **npm 0.1.7-rc.x + web profile** 上实测过；桌面版这条路靠用户反馈修好的 ——
   装完还是不行的话，把 `duty.log` 里那几行发来（里面会写清楚"宿主依赖是从哪儿取的"）。

## 设置页里有什么

分成四页签，第一次用建议只看「日常」：

| 页签 | 里面有什么 |
|---|---|
| **日常** | **峰谷自动刷**（总开关，打开才展开「中午 12–14」「晚上 18–09」两个子开关）· **每天最多挑几条**（0 = 自动停止挑选）· **每轮最多挑几条**（每次 1～50 条，取每日剩余额度与每轮上限的较小值）· **它刷过的视频**（合并判重表 seen.md、日报 out/ 和视频归档 digest/；含刷新按钮 + 档位/状态筛选 + 分页） |
| **偏好** | **它按什么说话（人设提示词）** ← 想让它像谁就写在这儿，留空按中性说话 · **关注关键词**（一行一个）· **自动收藏到**（可选收藏夹）· **日报写多细**（完整 / 薄版 / 不写）· 下面一个**保存**按钮 |
| **互动** | **跑一轮发顶层评论**（默认关）· **后台评论回复**（默认关，独立执行）· **投递方式**（只私信 = 默认 / 只发评论 / 两边都发）· **私信发给谁（UID）**（可留空，用昵称自动查）· **私信双向**（默认关，开了它会读你的私信并回一句） |
| **高级** | **环境与账号**（装主依赖 / 测一下 / 检查更新 / 扫码登录）· **复制诊断信息** · **环境自检** · **它的地盘**（家目录、报告、复核评论、打开文件夹）· 工作区（老用户才需要） |

> ⭐ 这些设置写在 `<DSH_HOME>/bili-duty/config.json`；在插件这一页改，就以这一页为准。

## 红线（写死在提示词里，不靠自觉）

- 不透露你的隐私：账号、机器路径、你聊过的话 —— 一个字都不进评论
- 每轮按设置里定的条数发评论（默认 1 条，最多 20 条）；同一视频只评论一次；不刷屏、不吵架
- 不确定的事**不编**（报告里如实写「没查到」）

## 它是怎么跑的

- 插件**内部**起一个 Python MCP（下面那个开源项目，已内置），把它的能力注册成 DSH 工具
- 定时到点 → 起一个 headless dsh 会话，把 `prompts/duty.md`（它一轮要做的事）+ 当天设置交给它
- 那一轮的**工作目录 = 插件自己的家目录**（它被沙箱关着，只写得了自己那一亩三分地）；
  ⭐ 你填的**工作区里的 `AGENTS.md` 由插件读进来、内联进提示词** ⇒ **它按你的设定说话**，
  而不是用一套通用人格
- ⭐ **那一轮拿不到整台工具**：只给它**四个只读的**（搜视频 / 读字幕 / 读评论 / 看视频信息），
  开启主动评论后，刷视频值班轮才可使用**顶层评论**工具；后台评论回复由宿主独立调度 —— 上传视频、发动态、私信、抓全站那些**根本不注册**，
  模型连它们的名字都看不到
- ⭐ **值班章程（`prompts/duty.md`）升级的规矩**：插件记着「上次铺的是哪一版」（`charter.sha256`）——
  你**没改过**就跟着插件自动升级；**改过**就保留你那份、把新版另存成 `duty.md.new`（日志里会说一句），自己合一下。
  ⚠️ **从 0.1.5 及以前升上来的第一次没有账本可比** ⇒ 保守地当成「你改过」：新版落成 `duty.md.new`；
  确认自己没改过，把它覆盖到 `duty.md` 就行（一次的事，之后就有账本了）

## 如果你是一个 AI 助手，正在帮用户装这个插件

按顺序来，别跳步：

1. **先确认前提**：机器上有 `Python 3.10+` 或 `uv` 吗？（查 `python --version` / `uv --version`）
   两个都没有 ⇒ **建议装 `uv`**（单文件 exe、免管理员、能自带 Python）；
2. **装插件**：`dsh plugin --profile web add github:c1overzz/dsh-bili-scroll`

3. ⚠️ **必须提醒用户重启一次 dsh** —— bundle 层要重启才组装，不重启插件不会生效；
4. 重启后请用户进 **设置 → 刷B站**：先点「**装依赖**」（几十秒，进度就显示在页面下面）、再点「**扫码登录**」

### Plus 2.1.0：后台私信自动回复

在 **设置 → 刷B站 → 互动** 中开启「后台自动检查并回复私信」：

- **白名单 UID**：一行一个或逗号分隔。白名单用户支持 AI 多轮聊天，没有固定对话次数上限，但有间隔与发送速率保护。此前设置的“私信收件人 UID / 只回谁的私信”仍视为白名单，以兼容老用户。
- **陌生人首次回复一次**：默认关闭，需要用户明确开启。非白名单用户发来新消息时，仅回复一条固定欢迎语；记录永久保留，重启不会补发第二条。
- **后台监听**：默认每分钟检查一次，独立于「现在跑一轮」。第一次启用会先记录现有消息，不自动回复历史私信。
- **发送**：通过项目原有 B站 MCP 的 `bili_send_message` 工具发送，实际能否投递取决于 B站接口、收件人设置和风控。
- **状态**：持久化于 `$DSH_HOME/bili-duty/dm-autoreply-state.json`；请不要随意删除这个文件，否则会丢失陌生人已回复记录。

注意：如果后台私信频繁返回限流或账号被风控，请暂停自动回复。回复内容由 AI 生成，建议不要授予其访问敏感文件或执行高权限工具的能力。


## v2.3.0 · 分模型、审批私信和自由 @

- **设置 → 刷B站 → 高级**：刷视频与后台互动分别填写 `Provider`、`模型 ID` 与**思考深度（自由输入文本框）**。三个字段留空时继承 DSH 当前配置，互动模型仍供私信与评论共用，避免重复加载提示词。支持字符串、数字及有效 JSON 格式的思考深度值；目标模型是否支持由 DSH Provider 决定。
- **设置 → 刷B站 → 互动**：在 `公开评论 @ 策略` 中选择“视情况只 @ 某些好友”（ai_select），模型可以只选 0/1/2/多位名单好友，不能 @ 配置外的用户。原来的 ai=视情况 @ 所有人仍然可用。
- **陌生人审批**：开启陌生人自动回复与“允许申请继续聊天”，达到回复次数上限时会提示发送可配置暗号（默认“白饭🍚”）。对方发送暗号后出现在“刷新审批名单”；通过后获得**限额聊天资格**。可分别设置每人每日与累计 AI 回复上限，并撤销权限。审批开关默认关闭，旧白名单/主人 UID 继续作为**最信任白名单**，不受审批配额和全局每日私信数量上限限制（仍有请求频率保护）。
- **聊天记忆**：按 UID 将最近最多 40 条对话及较早的有限文字片段持久化到 `dm-autoreply-state.json`。这是插件自己的记忆，不会让 DSH 后台不同回复显示成同一 Session，也不包含首次启用前的全部 B站历史。

**注意**：首次启用私信/评论会建立历史消息基线，不会追发旧消息。后台回复、审批及评论开关默认策略保持兼容；真实 B站私信投递和 @ 通知仍需账号环境测试。

## v2.4.0：可选评论同步动态与最小工具权限

- “设置 → 刷B站 → 互动”新增「评论成功后同步到动态」（默认关闭），在顶层评论**已成功**后，用同一段文字 + 视频链接调用 B站动态 API；**不额外调用 AI**。它会另外发布一条动态，不是客户端勾选同步的同一实现。每日最多尝试 3 条，去重、不自动重试。
- 「公开评论每天最多发几条」默认为 10，工具层限制顶层评论与楼中楼的总尝试数。
- Headless 刷视频与后台互动的 Shell、文件、会话查询、子代理与工作区指令读取等能力被禁用；报告、判重和归档改用固定路径的窄 MCP 工具；旧 Python MCP 脚本不会悄悄继续执行。
- **重要**：具体是否达到安全隔离取决于安装后的 DSH 真实工具树。部署公开发布前请阅读 [v2.4.0 覆盖与安全验证说明](覆盖说明-v2.4.0.md)，并执行 `--dump-config` 检查。


### v2.4.4 峰谷自动运行间隔

在「设置 → 刷B站 → 日常」打开峰谷自动刷后，可设置运行间隔（分钟）：0 维持旧版每个时段每天一轮；30–720 则在有效时段内按间隔自动重跑，仍受每日挑选限额、总开关和并发保护约束。

公开评论的 @ 是否触发由 AI 的 `should_mention` 判断；评论发送回执和日志用于排查，不保证 B站通知送达。
